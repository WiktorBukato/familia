# «Наша Фамилия»

Семейный архив для [familia-online.site](https://familia-online.site/). Astro собирает статический сайт, GitHub Pages отдаёт готовые файлы. Версия для онлайн-ревью доступна по адресу [/draftversion/](https://familia-online.site/draftversion/).

## Запуск на любом компьютере

Код новой версии находится в ветке [`review/nashi`](https://github.com/WiktorBukato/familia/tree/review/nashi). Нужны Git и Node.js 22.23.1 с npm. В PowerShell при ограничении запуска скриптов используйте `npm.cmd`.

```sh
git clone --branch review/nashi https://github.com/WiktorBukato/familia.git
cd familia
npm ci
npm run dev
```

Astro выводит адрес локального просмотра в терминал. Для проверки готовой сборки используйте `npm run build`, `npm run verify` и `npm run preview`. Для проверки префикса выполните `npm run build:draft`, `npm run verify:draft` и `npm run preview -- --base /draftversion/ --outDir dist-draft`.

Чтобы посмотреть семейный сайт из папки без локального HTTP, выполните `npm run build:review` и откройте `dist-review/index.html` в браузере. Для каждой следующей копии укажите новый каталог, например `npm run build:review -- dist-review-next`.

## Материалы

- [Familia — семейный архив в Google Drive](https://drive.google.com/drive/folders/1Jidu_bbxhulHuauuUsHermssaPdy6zF6) содержит исходные снимки, источники биографии и отдельный файл родословной. В подпапке `New` лежат подписанные снимки, в `Источники.md` — соответствие кадров людям. Откройте архив под аккаунтом с доступом. В Work можно подключить этот Google Drive и открыть репозиторий на ветке `review/nashi`.
- Для сборки достаточно Git и npm, все готовые изображения уже в ветке. При замене портрета подберите кадр, чтобы лицо было по центру и целиком помещалось в круглую маску, а затем сохраните квадратную копию WebP размером 512 × 512 без метаданных. Замените файл в `public/media/` или укажите новый путь и размеры в записи человека. Оригинал и его подпись сохраните в закрытом архиве.
- `src/data/family.json` содержит данные для сайта. У каждого человека устойчивый ID. Первый участник союза связывает его со своей родительской ветвью, второй отображается рядом. Идентификаторы детей подставляются из списка людей. Дерево проверяет связи, дубли и недостижимые записи при сборке. Текущая раскладка отображает один союз на человека.
- Статьи находятся в `src/content/pages/`. В Markdown указываются `kind` (`person`, `story` или `recipe`), уникальный в рубрике `slug`, `title`, `summary`, `published` и `person` для биографии либо `people` для истории или рецепта. Биографии доступны по `/<slug>/`, истории — по `/stories/<slug>/`, рецепты — по `/recipes/<slug>/`. Страница профиля и обратные ссылки на истории появляются из опубликованных записей автоматически.
- Портреты для сайта кладутся в `public/media/`, в дереве указываются их путь и размеры (`portrait.path`, `width`, `height`). Даты `birth` и `death` принимают год или дату в формате `ГГГГ-ММ-ДД`. Иллюстрации статей кладутся в `src/assets/`, в Markdown используются относительные пути. Готовая обложка подключается из `src/assets/cover.webp`. На странице размытие и затемнение по краям создаёт CSS. Сам файл обложки остаётся резким при открытии по прямому адресу.
- Этот репозиторий публичный. Храните необработанные фотографии, видео, полную родословную и тексты внутреннего ревью в закрытом Drive. Флаг `published: false` управляет сборкой, содержимое коммита при этом доступно на GitHub. До согласования состава материалов держите работу с семейными данными в локальной ветке.

## Ревью и публикация

1. Проверьте локально и согласуйте материалы к онлайн-ревью. Сохраните точный SHA принятого кандидата в Git и отправьте его в репозиторий.
2. Запустите [**Family archive · Publish**](https://github.com/WiktorBukato/familia/actions/workflows/pages.yml) на ветке `main`. Передайте SHA действующего сайта как `current`, а SHA проверенного коммита ветки `review/nashi` как `candidate`. Пока в корне старая версия, используйте `22675dda86fc32c4f7afa9bcbaef8a3d291ccb29` для `current`.
3. Проверьте оба сайта по HTTPS, включая старый адрес биографии, изображения, `/Test/`, навигацию и `noindex` для черновика. Страницы черновика публично доступны по прямой ссылке.
4. После финального ревью повторите запуск с SHA того же кандидата в `current` и пустым `candidate`. Проверьте главную, адрес биографии с косой чертой и без неё, `/Test/` и исчезновение черновика. Сохраните теги предыдущей рабочей и новой версий. Для отката передайте SHA предыдущего рабочего коммита в `current` с пустым `candidate`.

Для старой версии workflow копирует проверенные файлы напрямую из Git. Для новой публикуется только каталог сборки. Совместимость с `/Test/` и старым адресом портрета включена в сборку корня.
